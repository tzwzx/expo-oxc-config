# セルフ lint / format 導入 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** expo-oxc-config が配布している oxlint / oxfmt の共有設定を、このリポジトリ自身のコードにも適用し、CI で継続的に検査する。

**Architecture:** 消費側アプリと同じ入口（`defineConfig`）を自己参照で通す root 設定を追加し、それによって顕在化する既存の指摘 25 件を原則コード修正で解消する。CI はフリート共通の再利用 workflow（`tzwzx/expo-workflows`）に乗せる。

**Tech Stack:** oxlint 1.76.0 / oxfmt 0.61.0 / ultracite 7.9.4 / Bun / GitHub Actions

**設計ドキュメント:** `docs/superpowers/specs/2026-07-28-self-lint-design.md`

## Global Constraints

- **共有ルールを変更しない。** `oxlint.mjs` の `presets` / `ignorePatterns` / `rules` / `overrides` の**内容**（ルール名・設定値・override の `files`）は一切変えない。変更してよいのはキーの並び順と関数の書き方のみ。ここを緩めると消費側 7 アプリすべてに一斉に効く
- **`fixtures/` のコードを直さない。** 「本来なら指摘されるコード」を意図的に置いている場所
- **`postinstall` を追加しない。** このリポジトリは他アプリの依存として install されるため
- **新しいパッケージを追加する場合は `-E`（`--save-exact`）でバージョンを固定する**
- **コミットメッセージは Conventional Commits に準拠し、日本語で書く**
- **git のコミットは AI が実行しない。** 各タスクの Commit ステップはユーザーが実行するか、`/my:git-unlock` 済みのセッションでのみ AI が実行してよい
- 配列スプレッドの `?? []` は**必要**（`[...undefined]` は例外になる）。`no-useless-fallback-in-spread` が指摘するのはオブジェクトスプレッドの 1 箇所だけ

## File Structure

| ファイル | 責務 | 変更 |
| --- | --- | --- |
| `oxlint.config.ts` | このリポジトリ自身に共有 oxlint 設定を当てる入口 | 新規 |
| `oxfmt.config.ts` | このリポジトリ自身に共有 oxfmt 設定を当てる入口 | 新規 |
| `oxlint.mjs` | 配布する共有 oxlint 設定 | 指摘解消（並び順・関数形式・JSDoc） |
| `oxfmt.mjs` | 配布する共有 oxfmt 設定 | 指摘解消（関数形式・JSDoc） |
| `scripts/list-consumers.ts` | 消費側リポジトリの一覧出力 | 指摘解消 |
| `scripts/verify.ts` | ツールチェーンのスモークテスト | 指摘解消 |
| `package.json` | `lint` / `fix` / `rulesync:check` を追加 | 変更 |
| `.github/workflows/lint.yml` | CI（rulesync 差分 + lint） | 新規 |
| `.github/workflows/test.yml` | CI（`bun verify`） | 新規 |

- [ ] **Step 5: `oxlint.mjs` の関数 2 つをアロー関数式にし、JSDoc の `@param` に説明を足す**

ファイル末尾の `buildConfig` / `defineConfig` を丸ごと置き換える:

```js
/**
 * 共通設定にアプリ固有分をマージした config オブジェクトを返す。
 * 通常は defineConfig を使う（こちらは組み立て結果だけが欲しい場合の逃げ道）。
 * @param {{ ignorePatterns?: string[], overrides?: object[], rules?: object }} app アプリ固有の追加設定
 */
export const buildConfig = (app = {}) => ({
  extends: presets,
  ignorePatterns: [...ignorePatterns, ...(app.ignorePatterns ?? [])],
  overrides: [...overrides, ...(app.overrides ?? [])],
  rules: { ...rules, ...app.rules },
});

/**
 * 共通設定にアプリ固有分をマージして oxlint の設定として返す。
 * 各アプリの oxlint.config.ts はこれを default export するだけでよい。
 * @param {{ ignorePatterns?: string[], overrides?: object[], rules?: object }} app アプリ固有の追加設定
 */
export const defineConfig = (app = {}) => defineOxlintConfig(buildConfig(app));
```

**注意:** `rules` のオブジェクトスプレッドだけ `?? {}` を外す（`no-useless-fallback-in-spread` の指摘箇所）。`ignorePatterns` と `overrides` は**配列スプレッドなので `?? []` を残す** — 外すと `[...undefined]` で例外になる。

- [ ] **Step 6: `oxfmt.mjs` の関数 2 つをアロー関数式にし、JSDoc の `@param` に説明を足す**

```js
/**

 */

```

```ts
// この共有設定を使っているリポジトリを、同じ階層のディレクトリから見つけて出力する。
//
// アプリ名をドキュメントやスキルにハードコードすると、アプリが増減したときに
// 静かに古くなる。依存関係を実際に読んで判定することで、
// 「7本すべてで確認したつもりが6本だった」という取りこぼしを防ぐ。
//
// 使い方:
//   for d in $(bun scripts/list-consumers.ts); do ... done
import { readFileSync, readdirSync } from "node:fs";
import path from "node:path";

const SELF_DIR = path.resolve(import.meta.dirname, "..");
const PACKAGE_NAME = JSON.parse(
  readFileSync(path.join(SELF_DIR, "package.json"), "utf-8")
).name as string;
const SEARCH_ROOT = path.resolve(SELF_DIR, "..");

/** package.json が PACKAGE_NAME に依存していれば true */
const dependsOnSelf = (dir: string): boolean => {
  try {
    const pkg = JSON.parse(
      readFileSync(path.join(dir, "package.json"), "utf-8")
    ) as {
      dependencies?: Record<string, string>;
      devDependencies?: Record<string, string>;
    };
    return Boolean(
      pkg.dependencies?.[PACKAGE_NAME] ?? pkg.devDependencies?.[PACKAGE_NAME]
    );
  } catch {
    // package.json が無い / 壊れているディレクトリは対象外
    return false;
  }
};

const consumers = readdirSync(SEARCH_ROOT, { withFileTypes: true })
  .filter((entry) => entry.isDirectory() && entry.name !== "node_modules")
  .map((entry) => path.join(SEARCH_ROOT, entry.name))
  .filter((dir) => dir !== SELF_DIR && dependsOnSelf(dir))
  .sort((a, b) => a.localeCompare(b));

for (const dir of consumers) {
  process.stdout.write(`${dir}\n`);
}
```

変更点は 4 つ:

1. `import { dirname, join, resolve } from "node:path"` → `import path from "node:path"`（`unicorn/import-style`）
2. `dirname(fileURLToPath(import.meta.url))` → `import.meta.dirname`。これにより `node:url` の import が丸ごと不要になる（`unicorn/prefer-import-meta-properties`。Bun での動作は確認済み）
3. `"utf8"` → `"utf-8"` 2 箇所（`unicorn/text-encoding-identifier-case`）
4. `import { readdirSync, readFileSync }` → `import { readFileSync, readdirSync }`（`eslint/sort-imports` はケース区別の ASCII 順のため `F` < `d`）
